# 架构与可靠性

`cli.py` 只负责参数、配置和结果输出。`WorkflowEngine` 依赖可注入的 Builder、Flasher、SerialSession、ResetController、LogService 和 TestRunner，核心 `Protocol` 在 `core/interfaces.py`；替换后端不需要重写状态编排。

## 执行路径

验证配置/整个测试套件 → Git 状态与 diff → 构建 → 校验产物 → 订阅日志 → 打开唯一串口/接收线程 → 保持 NRST → 启动 CLI 子进程 → 按实测延迟释放 NRST → 等待连接/写入/校验 → 脉冲复位启动新固件 → 等待启动标志 → 协议测试 → 清理 → 归档。

`NORMAL` 连接可能停核，因此完整烧录校验后再次脉冲复位。日志从端口打开前已订阅，启动判定从最后一次脉冲前的字节偏移开始，避免旧固件启动信息制造成功。未配置启动标志时采用明确标记的弱判定延时。

## 边界

- `BuildService` 执行 argv 数组，禁止 shell 拼接；IAR 使用指定工程/配置，GCC 支持用户实际 Make/CMake/Ninja/自定义命令。构建失败、缺失/空 BIN、未更新产物全部停止。
- 新产物复制到运行目录，检查复制期间源未变化，计算 SHA-256。清单包含目标、地址来源、时间、大小、命令、源和快照路径。原有构建目录不删除。未触发重建的增量构建被保守判为 `ARTIFACT_STALE`，请配置真正生成 BIN 的命令。
- 产物哈希、清单和允许 Flash 区域在打开硬件前校验。地址来源须人工从 linker/正式布局核对；工具**不会解析任意 linker 脚本或证明用户填写的地址真实正确**。清单不是数字签名，只信任本机受信构建目录。
- `CubeProgrammer` 仅生成连接/写入/校验参数，不控制 RTS；`ResetAssistedConnectStrategy` 负责外部复位时序。成功同时要求退出码 0 及本机输出的连接、写入、校验正则匹配。原始日志保留，匹配时仅规范化 CRLF。
- `ProcessRunner` 直接把合并 stdout/stderr 写入磁盘，避免 PIPE 堵塞。取消/超时/回调失败后回收子进程树并等待；进程清理失败保留原错误及 PID。程序正常退出的子进程不应故意遗留后台任务，配置命令须以前台方式运行。
- `SerialSession` 在进程内排他持有端口，操作系统串口打开规则负责进程间互斥；一个读线程给日志和测试分发数据。测试接收缓冲默认 1 MiB，有界内存；绝对偏移过期显式失败，原始归档不截断。
- 测试逐项使用新的接收偏移、超时和全部规则断言，不接受“无响应也 PASS”。测试套件不包含可执行 Python，也不接受大模型决定 PASS。
- 每条路径进入清理：尝试释放 NRST、关闭串口、关闭日志；清理失败附加原始错误，不掩盖主故障。成功但清理失败整体不返回成功。
- 默认烧录一次，CLI 不提供无限重试。整个运行与单次构建/烧录均有超时；调用方可通过 `RunContext.cancelled` 取消。

## 证据与限制

运行目录不复用，结果原子写入 `run_summary.json`，事件追加到 JSONL。串口 RX 写 `serial.bin`，RX/TX 时间、hex 与 RX 偏移写 `serial.jsonl`；文本按配置增量解码，错误字节不会导致原始证据丢失。

Git diff 包含已有仓库的已跟踪更改；未跟踪文件列于 Git 状态，不自动归档任意文件内容或敏感文件。归档不是源码备份；Agent 新建文件须由其宿主另存补丁/证据。

无法保证断电、强杀 Python、内核/驱动崩溃时执行 finally。若软件失去硬件控制，不能据此声称 NRST 已释放；必须人工检查。硬件瞬态、电压与双输出争用也不能靠软件检查代替。
