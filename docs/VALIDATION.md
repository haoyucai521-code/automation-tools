# 验收与实机记录

截至 2026-10-23。本文是当前验证状态的集中入口；操作步骤见 [使用指南](USER_GUIDE.md)，架构见 [项目设计](design/PROJECT_DESIGN.md)。区分用户确认、自动化/Fake 测试、单板单次实测和连续稳定性，不把一项通过推广为全部支持。

## 当前结论与支持矩阵

**APM32E030 显示板的复位、连接、全片擦除、写入、校验和启动日志已经单次实测通过。** 正式 CLI 的外部 BIN 导入、真实工程构建到协议测试闭环及连续 20 次仍未验收；三个通用目标配置仍为 template，没有据此解锁全部安全标记。

| 对象/组合 | 构建验证 | 硬件验证 | 当前边界 |
| --- | --- | --- | --- |
| 合成 Cortex-M0 + ARM GCC | 本机真实编译、ELF→BIN、快照/清单通过 | 不操作硬件 | 不是实际固件工程或板卡支持声明 |
| STM32F030 + IAR/GCC | 后端 Fake 测试通过；真实固件未验收 | 本工具尚无该型号实测 | 用户确认共用烧录方式，不等于本工具已执行验收 |
| STM32F070 + IAR/GCC | 后端 Fake 测试通过；真实固件未验收 | 本工具尚无该型号实测 | 同上 |
| APM32E030 R157H 显示板 + 用户 BIN | 未执行构建，不知道 BIN 的完整可重建环境 | 极性、共线日志、连接、单次写入校验和后续全片擦除流程通过 | 一次性校准调用底层适配器；无伪造构建清单 |
| 正式 `run` + Fake 硬件 | 真实子进程合成构建通过 | Fake 启动/协议/清理通过 | 不能当作真实板卡端到端通过 |
| Agent 有限修复 | 回调、保护/上限/停止策略测试通过 | 未做真实已知 Bug 修复闭环 | 工具不调用模型，不替代宿主授权 |

APM32 共用 STM32 烧录方式是用户已确认实践，本机也已完成上述显示板试验；不把它写成厂商官方支持认证，也不因 CLI 显示 STM32 名称否定已通过的当前流程。

## 实机试验时间线

### RTS 与串口对照

证据目录：`runs/rts_rx_check_20261023T064852307876Z/`。

- True 第 1/2 轮各接收 6 秒，均 0 字节；False 第 1/2 轮各 6 秒，均收到 281 字节。
- False 下含 `Reset: Unknown/Normal`、`WELCOME TO ZOS`、版本 `1.0.0.0`、构建时间 `Oct 23 2026 14:31:01`、`open uart[0]`。
- 更早的两个状态均无数据的记录保留，不用它推断极性；最终采用重复成功的功能性对照，不声称测到了实际电压。

### 首次连接与写入（没有全片擦除）

- 只连接：`runs/20261023T065717058523Z_r157h_display_apm32_trial_2c324e3c/`，200 ms 释放成功。
- 备份/写入：`runs/20261023T065749683211Z_r157h_display_apm32_trial_31bfd724/`，先读 64 KB 备份，再从指定地址写入用户快照并 `-v`。
- CLI 退出码 0，明确输出 `File download complete`、`Download verified successfully`；只擦除 sectors `[0 28]`，不是全片擦除；未改 Option Bytes，未比较范围外 Flash 前后内容。
- 复位后出现有效启动日志。记录 1,025 个 RX 字节，原始 BIN 与 JSONL 的 RX 拼接一致；SWD 共线期间有非 UART 字节，原始数据未过滤。
- 释放复位/关闭串口/关闭日志均成功。摘要：[首次验证 JSON](tool-evidence/display_apm32_validation_2026-10-23.json)。

### 新流程：全片擦除、写入、校验与启动

用户要求增加全片擦除并继续实机验证后，执行独立一次试验；不是用首次按段擦除的记录替代：

1. 核对仍为当前目标和已知工具输出，备份当前全部 65,536 字节到 `flash_before.bin`。
2. 执行 `-e all`，退出码 0，明确输出 `Mass erase successfully achieved`。
3. 独立读回全部 64 KB 到 `flash_after_erase.bin`，65,536 字节均为 `0xFF`；确认空白后才写入。
4. 从指定平台起点写入相同 29,547 字节快照；CLI 输出写入完成及校验成功。
5. 再独立读取固件范围到 `firmware_readback.bin`，与快照逐字节一致。
6. 脉冲复位后收到 `WELCOME TO ZOS`、版本 `1.0.0.0`、构建时间 `Oct 23 2026 14:31:01`、`open uart[0]`。
7. 释放复位、关闭 COM7、关闭日志均成功，没有后台脚本继续占用 COM。关闭后物理电平未测量。

目录：`runs/20261023T071143715782Z_r157h_display_apm32_trial_4aa03135/`。摘要：[全片擦除验证 JSON](tool-evidence/display_apm32_mass_erase_2026-10-23.json)。

主要证据：`backup.log/flash_before.bin`、`erase.log`、`blank_check.log/flash_after_erase.bin`、`programmer.log`、`readback.log/firmware_readback.bin`、`external_image.json`、`run_summary.json`、`events.jsonl`、三类串口日志。快照和备份留在被 Git 忽略的运行目录，JSON 摘要保留在仓库；仅克隆仓库不能获得这些本机原始二进制。

**旧参数/KV 实际已擦除，没有自动恢复。** 空白检查发生在写入/启动前；固件启动后可能初始化参数，不宣称之后仍全为 `0xFF`。关闭串口后可能又被 RTS 保持复位，这是用户观察，不是已测波形。

## 阶段验收与剩余项

| 阶段 | 已有证据 | 尚未验收 |
| --- | --- | --- |
| 环境/硬件 | 本机工具、当前显示板/COM、功能性极性、连接时序 | 丝印独立核对、电压/开关瞬态波形、跨板时序范围 |
| 核心/CLI | 包、配置、模型、错误与 JSON/dry-run/report 自动化测试 | 真实环境组合覆盖 |
| 串口/复位 | Fake 回归、显示板共线日志与复位启动 | 断连/串口占用/超时等实机故障注入 |
| 构建/烧录 | 真实 GCC 合成编译、当前板外部 BIN 全擦/写入/回读 | IAR/真实固件工程构建、STM32 实物、正式外部 BIN 导入 |
| 日志/协议 | 确定性多规则与日志证据测试 | 真实双向协议和副作用恢复 |
| 完整工作流 | 合成链路和当前板单次底层校准 | 正式真实构建→硬件→协议闭环 |
| Agent | 白名单/上限/保护与停止回归 | 已知固件 Bug 的真实修复闭环 |
| 稳定性 | 记录了成功及失败实验，不推断其他板卡 | 连续 20 次无人干预及各准确型号支持矩阵扩充 |

后续验收应先明确目标、工程/构建、协议和允许动作，逐次记录 run_id、版本、原始证据与清理状态；不能把用户共用流程、模板字段或单次成功当成全部验收。
