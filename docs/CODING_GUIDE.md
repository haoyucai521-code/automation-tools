# 编码与测试规范

本文根据当前工具的代码、测试和已确认安全边界总结；不套用 MCU 的寄存器、DMA 或 RTOS 编码框架。模块和流程见 [项目设计](design/PROJECT_DESIGN.md)，行为与更新路由见 [AGENTS.md](../AGENTS.md)。

## Python 与风格

- Python 3.11+；保留 `src/embedded_auto` 布局和现有标准库、PyYAML、PySerial 依赖，不为简单功能新增框架。
- 使用四空格缩进；类名 `PascalCase`，函数/变量 `snake_case`，常量 `UPPER_SNAKE_CASE`。沿用所在文件的引号、导入和排版，不批量格式化无关代码。
- 公共接口、关键数据边界优先使用类型标注；结果对象沿用 dataclass，接口沿用 `Protocol` 和现有可注入依赖，不重复抽象。
- 新增/修改注释以中文为主，说明原因、边界和风险；保留标识符、协议和工具原文，不翻译日志证据，不重写历史英文注释来凑规范。
- 源码、配置和说明使用 UTF-8。编辑既有文件保留原换行方式；新文本推荐 LF，不顺带修复无关文件的空白。

## 分层与接口

- CLI 只做参数、配置、调用和输出；工作流负责执行顺序、状态和清理；服务负责独立业务；适配器封装外部工具/串口差异。
- 差异放入配置，不散落硬编码 COM、工程路径或时序。已确认的平台策略由现有配置校验和适配器执行，不通过新开关静默绕过。
- 服务返回 `OperationResult`；预期故障用 `ToolError` 和稳定错误码。新增错误码同步 `core/errors.py`，保持 JSON 与调用方契约一致。
- 不用 `except: pass` 吞故障；主错误和清理失败分别保留。边界可汇总意外错误，但必须留有可诊断信息。

## 外部进程、路径和产物

- 命令使用 argv 数组、`shell=False` 和现有 `ProcessRunner`，不得拼接 shell 或依赖 PowerShell 才能解释的字符串。
- 路径用 `pathlib.Path` 及统一配置解析，支持 Windows 空格、中文和绝对路径；不要改变调用方工作目录来隐式解析路径。
- 每个进程和整个运行均有明确超时，长等待可取消；失败、取消和中断后回收进程并记录清理失败，不留下未声明后台任务。
- 构建退出码 0 不是充分成功条件；沿用本次产物新鲜度、非空、快照、身份及范围检查。不得改时间戳或伪造 manifest。
- 仅在实际复制、完整性或信任边界需要时检查哈希，不为重复证明已保证的不变量增加全量读取。
- 擦除、写入和校验必须有退出状态及明确成功证据；失败不能继续后续阶段，不能把任意包含“success”的文本当作通用成功正则。

## 串口、复位和日志

- 一个物理串口只由 `SerialSession` 持有，一个接收循环分发数据；日志和测试不得分别读取底层端口。
- 复位通过同一串口会话控制，区分逻辑状态、API 布尔值与实测电平；普通脉冲宽度和 CLI 连接释放延迟分开。
- 接收订阅和证据文件先就绪，再打开接收；使用有界内存窗口和绝对偏移，过期窗口显式报错，不静默丢证据。
- 原始字节必须保留，文本解码/摘要不是替代品。关闭串口前尝试释放复位，不宣称已保证关闭后的物理状态。
- 通过 `try/finally` 等现有清理路径收束；历史接收错误不能阻止仍可用端口最后尝试释放复位。

## 确定性测试与安全

- 套件在操作硬件前完整预检；每例明确发送、超时和非空断言，全部条件满足才通过；不修改预期制造 PASS。
- 给本轮行为变更补对应 Fake/单元回归，优先覆盖失败阻断、取消、超时、资源释放和证据。不能把 Fake 成功写成实机验证。
- 使用标准库 `unittest`，测试放 `tests/`；本地命令见下。真实 ARM GCC 测试在工具缺失时可跳过，结果必须如实说明。
- 本机 `python3` 不可用时使用已安装的 `python`；不因名称约定安装第二套解释器。

```powershell
python -m unittest discover -s tests -v
```

- 仅文档/注释变更以链接、事实和差异检查为主；涉及打包或入口才增加对应验证，不重复执行无关测试或硬件写入。
- 硬件操作需单独明确授权，不默认运行桌面 BIN；不得将凭据、原始固件、Flash 备份和含敏感数据的运行日志提交到 Git。
- 文档与实现同任务收敛，更新路由见 `AGENTS.md`；不为验证方便永久放宽产物身份、保护文件、目标白名单或修复上限。
